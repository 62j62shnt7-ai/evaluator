# UT workspace implementation plan and audit

Goal: implement the user's supplied three-screen, single-workbook, batch-oriented redesign in the existing offline Python app.

Architecture: retain the revisioned SQLite services, whole-sheet importers, immutable source packages and draft component calculation engine. Add a workspace service and a bundled HTML/CSS/JS client. Preserve detailed tools through a secondary link. No new runtime dependencies.

## Audit (5 November 2026)

Inspected all source modules, workbook sheet inventories and actual UT/evaluation headers, populated rows, formulas and caches. Three workbooks: Separator XLSX (15 sheets), Separator XLSM (19 sheets), TL-B XLSX (22 sheets). Originals remain unchanged. Separator evaluation forms have 19 CML/head/shell rows and 19 nozzle rows. TL-B evaluation scenarios have 80 component records; tee/reducer sides require distinct assignments. Single UT sheets contain historical/current campaigns, while some evaluation current columns are projections. Do not treat projections as measurements.

Available references: API 570 fifth edition with A1; API 510 eleventh edition with E1/E2; B31.3 2024; B31.4 2025; B31.8 2025; VIII-1 2025; II-D Metric 2025. Existing planning/05 predates two supplied sources. Directly inspected API 570 7.1.2/7.2 and B31.8 841.1.1. Existing arithmetic is draft, and workbook B31.8-2020 scenarios must not become validated 2025 configurations. No B36 dimensional standard, verified material lookup registry, or independent approved engineering benchmark is supplied. Workbook properties are source-backed proposals, never a universal material database.

Reusable: extraction adapters, normalized histories, full package evidence, source profiles, Decimal calculations, revision conflict protection, undo, reports/backups. Replace default page/navigation and repeated matching/configuration forms. Keep original detailed routes.
